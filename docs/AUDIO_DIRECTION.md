# 《那个谁》音乐与声音

2026-09-13。本轮新增 `src/audio.mjs`，使用浏览器 Web Audio 实时演奏为游戏编写的旋律与和声。没有引入现成歌曲、外部音频链接、付费服务或需要下载的配乐文件。

## 听觉方向

校园的声音应给行走留出空间。白天是温暖、略带好奇的轻钢琴旋律，柔和拨弦接上句子之间的空隙；晚间速度放缓、音符变少，空气感和声陪伴收拾一天的心情。人物近景进一步降低配乐音量与旋律密度，让道具、动作和阅读成为注意力中心。

当前有两段原创八小节、四拍子曲式：

- **《九月的小路》**：76 BPM，八组旋律句与开放和弦，钢琴在中高音区，低音给出和声根音，拨弦作轻微回应。完整一轮约 25 秒。
- **《灯亮起来以后》**：60 BPM，八组更稀疏的旋律，延长留白和和声尾音。完整一轮约 32 秒。19:00 起使用；章末回忆也采用此段。

两段均逐小节写出旋律和和声，不通过重复一个提示音制造背景声。谱面使用 MIDI 音高、拍位、时值与力度，集中保存在 `AUDIO_SCORES` 中，后续可以直接调整具体音符和曲式。

## 音色与空间

- 钢琴使用多谐波周期波形、短促的琴槌噪声、随时间收拢的低通滤波，以及快起音／自然衰减包络，形成轻钢琴的合成音色。它不是钢琴录音采样。
- 拨弦使用不同的谐波比例、较短的音量衰减和收拢更快的滤波。它与钢琴有不同的力度和声像，不与主旋律争抢同一位置。
- 空气感和声使用轻微失谐的成对正弦波、缓慢起音和释放，保持较低音量。
- 一份程序生成的短双声道脉冲响应提供柔和空间尾音；轻微左右声像区分钢琴和拨弦，主输出经过温和压缩以限制叠音峰值。

脉冲响应、琴槌和道具噪声缓冲都只在首次解锁音频时创建一次。它们留在内存，不生成文件、不访问网络。

## 场景规则

`setScene` 接收当前模式、校园分钟数和可选地点：

- `campus`：正常校园配乐；图书馆进一步降低音量与拨弦密度。
- `encounter`：保留所在昼夜的和声，减少旋律音符、每小节只留一处拨弦，音量降至正常比例的 38%。
- `practice`：停止背景乐队列并静音背景总线及其混响尾音，保留训练节拍与操作音效。
- `ending`：使用夜间乐谱，音量低于白天探索。
- `title`：静音，不在初次扉页自动发声。

同一昼夜内切换近景时保持乐曲拍位，已发出的音符自然衰减，只替换尚未发出的短队列。昼夜变化也按拍位衔接新速度。设置、页面隐藏和练习结束不会积压一串需要补播的音符。

音效与音乐独立开关；音乐音量范围为 0—1，只影响背景总线。模块默认两者开启，默认音乐音量 0.65；当前游戏界面主动配置为 35%，并由设置面板控制。旧版 `sound=false` 偏好由主界面迁移为初始音乐关闭，尊重之前的静音选择。

## 道具和动作音效

近景直接使用剧本的道具／动作键调用 `cue(name)`：

- `receipt`、`book`、`map`、`notebook`、`bottle-note`、`paper`：短促、柔和的翻纸声。
- `write`：较细的纸面摩擦。
- `uniform`、`fold`、`cap`：较低频的布料轻响。
- `hanger`、`cap-buckle`：轻微的衣架或扣件碰触。
- `bottle`、`tray`、`cup`、`water-bucket`：几组低音量衰减泛音形成杯子／餐盘轻碰。
- `step`、`shoes`：低频落脚和短表面噪声。
- `clap`：两次极短的带通噪声形成克制的拍手声。

`wave`、`listen`、`nod` 等没有必要发声的动作保持安静。未知 cue 同样静默。另保留 `recognition`、`memory`、`morning`、`evening`、`event`、`complete` 的短旋律提示接口，当前无需每次翻页都调用。

## 接入接口

```js
import { createAudio } from './audio.mjs';

const audio = createAudio();
audio.configure({ sound: true, music: true, volume: 0.35 });
audio.setScene({ mode: 'campus', minute: 920 });

// 第一次调用必须来自“开始游戏”等用户点击。
await audio.resume();

// 后续只更新情境；不会创建或解锁 AudioContext。
audio.setScene({ mode: 'encounter', minute: 1050, locationId: 'shade' });
audio.cue('bottle');

// 隐藏页面：清理调度、停止发声。
await audio.suspend();

// 用户返回已解锁的页面，恢复时从新队列开始。
await audio.resume();

// 页面或宿主销毁时释放资源；同一实例随后不可再启动。
await audio.dispose();
```

完整返回接口：`init()`、`configure()`、`setScene()`、`note(freq, length, volume, kind)`、`step()`、`click()`、`cue(name)`、`suspend()`、`resume()`、`dispose()`。`init` 是 `resume` 的别名，同一次手势只需调用其中一个。主界面负责存储偏好和判断首次解锁；其他方法不会隐式调用解锁。

`setScene` 可在主循环调用：先比较模式／昼夜／图书馆三个维度的键，未变化时直接返回，不在每帧重建乐谱或计时器。音频不调用游戏时间推进函数，对话里的音乐可以继续，但游戏时间仍由原暂停规则控制。

## 调度与释放

每个音频实例最多保留一个 75 毫秒调度器，每次只向前安排 200 毫秒。调度游标防止同一音符重复入队；若页面调度迟到，跳过已经过去的音符，不追赶播放。暂停清除计时器、停止和断开所有声部；恢复重新建立短队列，不叠加旧音符。快速隐藏／返回时会等待尚未完成的 suspension，避免恢复请求被更晚完成的暂停覆盖。

单个声部有明确结束时刻，结束回调断开振荡器、滤波、声像和音量节点；并限制同时存活的声部数量。永久输出图和共享缓冲每个实例只创建一次，`dispose` 清理声部、调度器、连接和 AudioContext。没有 AudioContext 的 Node 或浏览器中，所有音频方法安全无操作。

## 验证

`node --test tests/audio.test.mjs` 当前 11 项通过，覆盖：八小节乐谱与事件有效性、昼夜与近景配器、音乐和音效独立控制、音量边界、跨循环不重复调度、延迟不补播、暂停／恢复、无手势不分配音频、一次实例仅一个计时器、异步暂停竞态，以及近景实际道具键的音效接入。

乐谱和调度测试直接使用生产数据与传输逻辑；少量音频设备替身只验证浏览器边界的解锁、静音和资源释放。测试不代替扬声器或耳机的听感验收；实际音量、音色与移动端恢复由浏览器试玩进一步确认。

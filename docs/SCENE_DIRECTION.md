# 《那个谁》近景演出方向

2026-09-13。本文记录新增的 `src/scene-content.mjs` 及其数据契约。近景分镜的自动化契约测试已经完成；本文不代表画面、动画或浏览器端交互已经验收。

## 让一件小事有发生的过程

近景承担的是“看见、停留、回应”的过程。玩家走近一个人后，先看见此刻的地点和动作，再留意一个具体细节，最后决定怎么回应。它不把一段文字拆成许多必须点击的提示，也不通过自动替玩家作决定来制造参与感。

例如第一次在图书馆遇见陈可：小票被风吹落，人物伸手没够到；镜头让玩家看一眼纸角与摊开的地图。此时可以观察，但不会替玩家先捡起来。到原有选项出现后，玩家才决定捡小票、询问地图或关小窗户。三个反应分别以小票、地图和停下来的书页为中心，手势与物件随已选的行动变化。

这套处理也适用于人物逐渐清晰：先记住一个人怎样拿东西、怎样停顿、怎样给人让位置，再逐渐辨认面容。动作和物件提供认识的依据；关系阶段仍由现有模拟层决定，演出点击不发放额外羁绊。

## 两类年龄都能进入的细节

大学是故事发生的当下。十七至十九岁的玩家可以通过这些小事试着理解新的生活；毕业多年的人也可以认出相似的身体感受和人际分寸。场景不要求玩家拥有某个年代、某种恋爱、某个家庭或性格经历。

选择的细节以仍然能发生的校园生活为主：

- **衣架与行李**：新宿舍里还不知道东西该放哪里；衣架先碰出声音，自我介绍慢一点也没关系。
- **帽扣和衣角**：军训服不合身，帽扣收到最短仍会歪。陌生人的第一个特点可以非常小，不必先靠五官来记住。
- **书签小票与手绘地图**：同一个东西有好几种用途。书本只是这个人的一部分，空白页里还可以有猫、阴凉的小路和未来的排练室。
- **餐盘与桌号**：新食堂里找位子、关掉过度准备的攻略、在小群里发出第一条生活消息，比“马上成为最好的朋友”更贴近相识的过程。
- **挂断的电话和床边的鞋**：刚向家里说完“挺好的”，可以先坐一会儿。陪伴既可以聊天，也可以不急着解释。
- **水壶纸条与名单旁的小字**：教官既有口令，也有被反复贴好的手写纸条。一个人愿意在自己的提醒中记下“语气”，比一段总结性说教更有说服力。
- **没有按下的手表**：跑道上的人可以先停止计时，再慢慢说出除了跑得快以外，还想做什么。

这些物件不会被设计成“只有老同学才懂”的怀旧密码，也不替年轻玩家预告多年后的遗憾。人物关系保留朋友、室友、同学与教官之间本身的分量，不默认把亲近处理成恋爱。

## 十七段近景怎样组织

十二段个人剧情与五段校历剧情都已有独立的镜头配置。每条 `dialogue.lines` 原文对应一个 beat，内容和先后顺序不变。不是从人物素材库随机挑一个动作套上去。

李屿的三段近景依次围绕帽扣、树荫中的空位与水杯、没有按下的手表。相识时有招手与拧杯盖的细节；理解后的一条反应会从收起手表走向跑道上的树影。树荫与操场都可能承接初见，布景跟随实际靠近的地点。

陈可的三段近景从纸票和地图转到停在同一页的书，再转到耳机与笔记本。纸票的观察先于玩家是否捡起的决定；提出音乐话题后，也保留只听几句或合上本子的不同节奏。

周舟的三段近景从宿舍的衣架和行李转到食堂餐盘，再到挂断的电话。安静陪坐的反应使用宽镜头和倾听，主动出去走走才使用走动。第一次相识不提前在屏幕上放出周舟的姓名。

王教官的三段近景从挪入阴影的水杯转到水壶上的手写字，再转到名单末尾的提醒。提出不同意见后，先保留一个停顿，再给写下提醒的细节镜头。初见时仍只称教官。

校历活动使用日程规定的地点：领衣在校门，其余四段在操场。站军姿让晃动和半步空间能被看见；拉歌把注意力放到起声前的停顿与膝上的拍子；领队保留脚步、摆臂与身后的人；结营先看最后的行进，再看收起的哨子，最后把视野还给散场的人群。

环境观察、日常碰面、回寝休息与整理章末回忆也有兜底演出。整理回忆只有在玩家已经选定后才出现叠好训练服的动作；选择前仍是观察窗边的衣服。

## 镜头与点击边界

`focus` 使用三个值：`wide` 建立人与场所的关系，`person` 接住一句话或一个回应，`detail` 把注意力交给正在变化的小物件。两句的短场景可以从物件细节开始，再回到人物；更长场景则给环境、停顿和反应各留出位置，不强行要求每段同一顺序。

`gesture` 只使用渲染层约定的十二个动作：`idle`、`wave`、`offer`、`reach`、`nod`、`listen`、`step`、`clap`、`sway`、`fold`、`point`、`write`。动作描述当前句已经发生的行为；选项之前不会通过点击把某个尚未选定的玩家分支执行掉。分镜层不指定性别化动作，也不新增主角的脸或身世。

`actionLabel` 是可选观察热点，例如“看看被风翻起的小票”“听听碰在一起的衣架”“看看一大一小的手写字”。它让玩家把注意力放到画面中的位置，由显示层播放对应镜头后前进。最后一个 beat 不再提供观察热点，交还原有选项或“继续”。显示层应同时提供直接回应的入口，让玩家能够跳过演出到达原选项；这不会替玩家作选择，也不会改变故事结果。

默认动作由首位说话人执行；有明确归属的镜头附加 `actor`，值为 `player` 或有效 NPC ID。例如递还小票和走出队列由玩家执行，站军姿时走近的是教官，碰鞋尖的是室友。手中物件确实交给玩家时另加 `propOwner: player`，由前景主角手部呈现。脚步中的 `shoes` 留在脚下，不能仅因 actor 是玩家就把鞋画到手上。

## 数据接口与资产键

`getScenePlan(dialogue, state)` 返回全新的纯数据对象：

- `id`：由对话来源、节点、choice／reaction 阶段及已选下标组成，同一状态可重复生成。
- `locationId`：六个校园地点之一。校历使用活动地点；可跨地点的初见使用玩家当前靠近的合法地点；日常碰面使用当前位置。
- `ambience`：当前地点的简短环境文字，19:00 以后切换晚间氛围。它不加入人物姓名或未发生的回忆。
- `title`：原有对话标题，未提供标题时使用安全兜底。
- `prop`：当前场景主要物件的语义键；每个 beat 可用自己的 `prop` 切换特写物件。
- `cast`：NPC ID 数组，首位是有效的当前说话人，其余为该场景实际需要的配角。主角由渲染层默认呈现，环境对话不虚构 NPC。
- `beats`：与合法原文行逐条对应的 `{ text, focus, gesture, prop, actionLabel?, actor?, propOwner? }`。

与美术实现协调的物件键为：`none`、`hanger`、`suitcase`、`cap`、`cap-buckle`、`receipt`、`book`、`map`、`tray`、`phone`、`bottle`、`bottle-note`、`whistle`、`notebook`、`earphones`、`water-bucket`、`uniform`、`shoes`、`bench`、`watch`。帽扣和水壶纸条是同一物件的细节表现，不是新增角色资产。`none` 用于声音、手势、环境或不需要固定道具的画面。

模块同时导出 `SCENE_PROPS`、`SCENE_GESTURES` 与 `SCENE_FOCUSES`，供实现与测试核对。

## 读档与现有状态的关系

函数只读取传入状态，不移动玩家、不推进时间、不改关系、不记录经历。姓名仍由现有关系状态和原文自我介绍决定；分镜添加的环境、热点和标题不会提前补出未知姓名。

对话可能带有迟到、前次帮助、早餐约定等前情插句。实现按原文识别既有镜头，而不是只用数组下标套用，因此插句不会把后面的杯盖特写错误移到自我介绍上。

已保存的 reaction 使用 `selected` 恢复对应分支。领队练习的特殊回应使用实际保存的命中数和是否跳过，分别呈现稳下来的脚步、没踩准后的停顿、先观察队列；不会把跳过演成成功完成。缺少某个字段或未识别的新节点时保留已有文字并生成安全的通用镜头。

逐镜进度、热点动画、直接回应、降低动态效果以及镜头是否已看过，由显示层管理。镜头的省略不应调用额外的 `choose()`，也不应增加认识程度。

## 当前验证范围

`node --test tests/scene-content.test.mjs` 共 83 项通过，覆盖十七个选择场景与五十个反应分支、全部物件与动作合法值、原文逐行保持、活动地点、未知姓名不提前进入新增内容、前情与迟到插句、实际练习存档、环境与日常碰面、章末选择前后动作边界、纯函数无状态变更，以及损坏或缺失字段的兜底。额外验证玩家递物、教官走近和室友碰鞋的动作归属，避免把所有动作都交给主说话人。

下一步仍需在实际页面中检查人物动作是否归属正确、细节热点是否点得中、近景和文字是否遮挡、手机竖屏可读性、降低动态效果，以及从任意演出阶段直接回应或读档的行为。上述浏览器和视觉检查不由本数据模块测试替代。
